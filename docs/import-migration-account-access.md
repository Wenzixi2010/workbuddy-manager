# 账号 JSON 导入、Key 权限与旧版数据迁移

## JSON 导入

在「账号」页点击 **JSON 导入**，粘贴凭证后导入当前分组；原有「导入/导出账号」文件上传仍然保留。

支持：

- 单个标准凭证：`{"account":{"uid":"..."},"auth":{"accessToken":"...","refreshToken":"..."}}`
- 扁平凭证及其数组：`[{"uid":"...","access_token":"..."}]`
- 旧版导出的 `items` / `accounts` 包装，其中的条目可以是对象或 JSON 字符串。
- 带 `auth_json` 的旧版记录、workbuddy-switch 的 `auth_raw` 和 snake_case 凭证。
- 同时包含扁平凭证、`profile_raw`、`auth_raw` 和 `device.deviceToken` 的账号数组；未提供 `realm` 时兼容 `variant` 的 `cn` / `global`。

文件上传与粘贴文本使用同一套解析。当前 `auth` / `account` / 顶层字段优先，`profile_raw` 只补缺失的身份信息，`auth_raw` 只补缺失凭证，不会用旧快照覆盖当前 Token、到期时间或设备令牌。外部管理器的余额、冷却、启停和操作时间快照不会恢复成运行状态。

`proxy` 是面板的**线路名**，不是代理 URL 或 `proxySlot`。导入指定了线路时，该同名线路必须已在面板配置并启用；线路不存在、停用或配置无效会明确拒绝，不会静默改成直连。

每份 JSON 最大 2 MB、最多 500 个条目。默认跳过重复账号；勾选覆盖后更新凭证，但保留手动停用状态、账号权限、现有设备令牌/线路/权重（导入未提供这些元数据时）。每条独立处理，结果显示新增、覆盖、拒绝和失败数量。

粘贴文本的弹窗保持固定的响应式宽高，长 JSON 在输入框内部横向 / 纵向滚动；标题和提交按钮始终在滚动区域外。

新版客户端的加密凭证不能直接导入：请在旧版导出**明文备份**。加密对象不会被误当成字符串 Token 保存。

## 两个方向的权限同时生效

| 设置位置 | 含义 | 未选择时 |
| --- | --- | --- |
| Key 编辑 → 此 Key 可用的账号 | 限制该 Key 可调用的账号集合 | 仅使用公共池 |
| 账号操作 → Key 使用权限 | 限制该账号允许的 Key 集合 | 账号侧不作额外限制 |

两个条件取**交集**：保存账号 A 的允许 Key 时，会自动把 A 加入所选 Key 的可用账号范围；原本没绑定账号的 Key 只勾选 A，已有手动绑定与模式保持不变，其它账号由用户在 Key 设置中自行增删。清空账号侧名单不会自动清除 Key 既有账号范围。没选择账号范围的 Key 不会调用已专属占用的账号，即使出现在该账号的允许名单中。

Key 账号范围有两种模式：

- **仅限制此 Key**：不会占用所选账号；公共账号继续供其他 Key 使用。
- **独占绑定**：所选账号退出公共池，只允许独占绑定它的 Key；多个独占 Key 可共享。停用 Key 不释放占用，取消绑定或删除 Key 才释放。

账号侧的限制与独占绑定分别保存。清空账号侧名单不会解除其他 Key 的独占绑定。允许名单中的 Key 被删除时，不会把该账号自动开放成公共账号；管理员需明确解除限制。专属账号移动分组前必须先解除权限/独占绑定，防止移动后意外变为公共账号。

无可用的授权账号时请求失败，**不会回退到范围外账号**。OpenAI v1/v2、Responses、Anthropic Messages、聊天测试台及模型列表查询均遵守此规则；上游的粘性会话、轮换重试、大请求回退也会重新过滤。

### 部署要求

此功能需要管理端与包含 `0051-account-key-scope.patch` 的上游一起部署。现有发布/Windows 构建流程会自动应用 `dev/upstream-patches/` 中的补丁；仅更新前端或 Python 管理端不够。

- 上游必须配置 `api_key`，用于验证管理端签名。
- 有账号范围限制时，管理端先检查 `/status` 的 `account_scope_version: 1`。
- 推理和模型查询走 `/v1/scoped/chat/completions`、`/v2/scoped/chat/completions`、`/v1/scoped/models`，避免旧版忽略请求头造成越权；不支持时拒绝，不回落普通接口。
- 不要把上游管理用 `api_key` 发给下游用户；应只分发面板生成的 Key，并限制上游端口的外部访问。
- 规则按每次新请求计算；已经开始的请求不会因之后编辑权限而被中断。

## 创建自定义 Key

「密钥 → 新建密钥」可开启 **自定义 Key**，输入完整凭证。关闭开关或留空仍自动生成；不会自动加 `wbk_` 等前缀，也不会改写输入内容。

自定义值必须为 16–256 位英文字母、数字、下划线或连字符，建议至少 32 位随机字符串。相同值（包括已停用、过期或迁入的 Key）不能重复创建，并发创建也只会成功一条。

此选项仅用于新建，不会修改已有 Key。创建后与自动生成的 Key 一样支持查看、复制、额度和账号范围限制；输入框的明文不会保存在浏览器本地存储，关闭创建弹窗即清除。

## 再次查看 Key

「密钥」列表的 **查看** 按钮打开完整 Key 弹窗，可再次复制；关闭弹窗会清除页面中的明文状态。明文不随列表接口下发，每次查看仍受管理员鉴权和审计保护。

历史上只保存哈希、没有明文的 Key 无法逆向恢复，系统会说明原因；新建 Key 和从旧库成功迁入的完整 Key 均可再次查看。

## SQLite 迁移

入口：**账号 → 数据迁移**（`/migration`）。

1. 先备份当前系统。关闭旧版后复制 `workbuddy_admin.db`，或用 SQLite backup 导出一致性快照。**不要单独复制仍在 WAL 模式写入中的 db**：最新数据可能在 `-wal` 中，单个 db 看似正常也可能缺数据。
2. 选择当前系统的目标账号分组，上传完整 SQLite 文件（最大 1 GB（1024 MB））。
3. 可选覆盖同 UID 账号、导入历史调用日志（分批读取，不再限制 10 万条）；默认不覆盖、不导入日志。
4. 点击 **预览数据**。预览不写入账号或 Key，不回传 Token；检查新增数量和警告。
5. 点击 **确认导入**，确认后写入，并请求重启目标上游。

迁移内容：

- 账号凭证、昵称、设备令牌、可兼容元数据、创建时间与停用状态。
- 原 Key 字符串、启停状态、积分额度、已用积分、创建时间。
- Key 主账号/关联表的多账号绑定、白名单/独占模式。
- 模型分组与启用模型规则转换为每把 Key 的模型白名单。
- 可选的历史调用日志、每日/每小时用量统计；重复导入不会重复累计。

重复 Key 按哈希跳过，**不覆盖当前配置和已用额度**。缺少可验证完整密钥时跳过该 Key；无法迁移的独占 Key 仍会让相应账号保持非公共状态，待管理员手工处理。关联账号无效时不会把该 Key 悄悄改为公共池 Key。无法表达的空模型范围、零额度或独立并发/速率上限会让相关 Key 安全停用，并显示原因。

不迁移旧版管理员、系统设置、定时任务、运行时冷却/熔断和余额快照；请重新配置并刷新余额。未在新版配置的代理线路不会自动创建。

源库以只读方式处理，原文件不被修改。数据库写入使用事务，处理失败时回滚并恢复账号文件；进程崩溃/断电不等于可捕获异常，仍应保留迁移前备份。

## 管理员用户名与密码

「设置 → 管理用户」新增 **修改用户名**，包括默认 `admin`。用户名 1–32 位，不可含空白、斜杠或控制字符，不能与现有用户重名（忽略大小写检查重复）。改名保留原密码与角色，但会注销该用户全部已有会话；修改自己后用新名字和原密码重新登录。仍然必须保留至少一个管理员。

新建、重置密码与 `WB_ADMIN_PASSWORD` 统一要求至少 **8 位**，无大小写/数字/特殊字符组合要求。仍建议使用长随机密码，并保留登录防爆破和 HTTPS/SSH 访问保护。

大文件迁移改为分块落盘（最多 1 MB/块）和日志批量读取（500 条/批），不再限制日志 10 万条。上传最大 **1 GB（1024 MB）**；代理需要为 multipart 开销预留空间，Nginx 可设 `client_max_body_size 1100m`。完整更新命令见 [Linux 部署指南](linux-docker-compose.md)。

## 当前管理端可恢复 SQLite 备份

「数据迁移」可导出含所有分组账号凭据、完整 Key、双向权限、备注、日志和用量的备份。导入入口自动识别新版，先预览、勾选覆盖再替换业务数据；旧版仍合并导入。在线恢复保留管理员和部署/更新配置，多分组按同名目标重映射。恢复前停止上游与后台任务，完成后手动启动。规则见 [SQLite 备份与恢复说明](sqlite-export.md)。
