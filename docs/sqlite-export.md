# 可恢复 SQLite 备份（包含账号凭据）

## 导出与包含内容

管理员进入「账号 → 数据迁移」，点击「导出 SQLite」并确认，浏览器下载带日期的 `.sqlite3`。

- 所有分组账号原始 JSON：access/refresh Token、device token、昵称、有效期、企业信息、线路/权重，以及 `.disabled` 状态。
- 数据库：Key 完整值、额度和已用量、账号侧允许 Key、Key 侧账号范围/独占、模型限制、备注、添加时间、日志、用量、IP 规则和红包等。
- 备份版本、分组清单和凭据表仅添加在导出副本，不改变运行中库的结构。

SQLite 在线 backup API 包含已提交 WAL 数据，按页复制，不将整库读入 JS。账号文件逐个原子读取并验证，异常凭据或重复身份会中止导出，不生成缺账号的“成功备份”。数据库和多个上游 JSON 不是跨进程全局同一时刻的快照；精确全系统备份仍需停止服务后备份所有目录。

单文件上限 1 GB，账号至多 5000，单凭据 2 MB，凭据总量 64 MB。超限先归档/清理历史日志，或用停机目录备份。仅会话管理员操作，不接受 API Token；下载链接绑定生成者、单次使用、五分钟过期，结束/中断/过期时清理临时副本。

## 同一导入入口恢复

1. 先备份当前系统，谨慎回滚旧备份，不丢弃新增凭据和用量。
2. 停止相关上游容器和后台任务，避免旧内存池/续期把恢复后的 Token 再写成旧值。管理端保持运行以使用恢复页；期间不要增删账号和 Key。
3. 上传新版 `.sqlite3`，选择默认上游。分组下拉只给旧版单池迁移指定目标，新版涵盖全部匹配分组，不允许合并到其它池。
4. 选择是否恢复历史日志/用量，勾选允许覆盖，点击预览。检查“当前管理端恢复备份”、账号/Key/日志数量和警告。
5. 确认导入，再次确认替换业务数据。完成后由宿主机启动上游并检查账号、Key 原字符串、双向绑定、禁用状态和调用。

旧版仍按合并迁移处理，重复 Key 跳过、不覆盖配置。新版恢复替换目标目录里的账号和全局业务表：删除备份没有的账号/Key，保留备份中原 Key ID 和权限关系。

日志选中时恢复调用/签到/任务日志及用量；没选时清空这些当前记录，避免旧日志错误关联恢复后不同的 Key ID。审计日志保留。

多分组按来源名称匹配现有分组，ID/目录重映射到本机。新机先创建同名分组和本机目录；缺少映射、共享目录、额外目标分组均拒绝，不偷偷把专属账号转公共账号。

上一轮无账号/标记的纯 SQLite 不能完成这种恢复，请升级后重新导出。

## 目标机器保留配置

在线恢复不覆盖管理员 `users.json`、会话 secret、管理 API Token、审计日志、上游 URL/内部 Key/目录/容器名、上游 `config.json`、`.env`、GitHub/更新配置及其它非白名单设置。

账号权限中的已删除 Key 会转为拒绝占位，避免编号将来复用时意外授权新 Key；专属账号不会因此变为公共账号。恢复 IP 规则可能影响客户端访问，请检查新服务器的访问地址。

业务设置恢复白名单：模型映射、日常任务、任务领取/Token 刷新计划、代理池/粘滞/总开关。恢复后核对新机计划和代理能否使用。恢复不安装上传库里的 SQL/触发器/任意文件路径，只使用现有程序表结构及现有目标目录。

要迁移整个服务器的管理员和环境，外部配置及上游 `data/` 仍需安全备份；SQLite 不重建 Docker 部署。

## 安全与故障

备份包含真正可用的账号 Token、完整 Key 和敏感设置，必须加密保管，不上传 GitHub、不公开分享。GitHub 仅同步源码。

先验证 schema/凭据/分组/权限，在处理到的失败时回滚 DB 与账号替换；磁盘故障/断电超出在线事务范围，必须预先离机备份。文件锁只覆盖管理端，不阻止 Go 上游/其它进程写入；这些写者必须停止。恢复不自动重启旧内存池，防止停机 flush 覆盖新文件；手动启动已停止的上游。

默认教程：在 `/opt/workbuddy-stack` 执行 `docker compose start workbuddy2api`。如果后台任务会续期，恢复前也应在面板关闭相关计划。

## API

- `POST /api/migration/sqlite/export` 返回 ticket、filename、expires_in。
- `GET /api/migration/sqlite/export/{ticket}` 单次下载。
- `POST /api/migration/sqlite` 参数 preview、overwrite、include_logs：上传旧库或新备份，自动识别；新版返回 format=native、requires_overwrite=true。

全部要求管理员会话。短期 ticket 保存在默认单 worker 内存中，服务重启后重新导出。
