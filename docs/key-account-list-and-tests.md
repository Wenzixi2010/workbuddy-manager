# 模型分组、精简 Key 列表和模型测试弹窗

## 模型分组

进入「密钥 → 模型分组」创建/编辑分组，在分组设置选择允许使用的模型（至少一个）。可限制国内/国际版本，也可不限制版本。

Key 设置里只选择模型分组，不再单独选择模型。分组中的模型权限由所有选用它的 Key 共享，修改后对后续请求生效。未选分组不在列表显示分组标签；选了才显示分组名。限定版本的分组会让 Key 设置跟随该版本；模型调用仍须使用正确的版本前缀。

旧 Key 的独立模型白名单在升级时自动转换为「原模型限制 · Key名称」分组，保留原限制，不因界面变化意外放宽权限。解除分组代表主动取消这一层模型限制。已被 Key 使用的分组不能删除；空/无效/已丢失分组拒绝模型调用，不解释为不限模型。

备份包含模型分组和 Key 的关联，旧版没有分组表的当前备份仍可恢复，其 Key 原模型限制自动转换为分组。

## 精简 Key 列表

移除可使用账号列。只有 Key 保存了独占绑定且选中了账号时，在 Key 名称下显示独占账号（昵称/备注、ID、数量，可展开）。普通白名单/公共池不显示账号块。不添加额外宽列，未设置模型分组的行也不显示分组标签。

账号权限判断与正式调用保持原样；只调整展示，不释放已停用 Key 的独占账号。

## 模型测试弹窗

点击模型行「测试」先打开弹窗，不立即发送请求。弹窗内部有「测试账号」下拉、刷新账号按钮和「发送 Ciallo」按钮；选择账号后再发送，结果/本次账号显示在同一弹窗。

默认公共池；管理员也可选默认上游的单个专属账号做一次诊断。后端仍校验存在/版本/凭据及账号隔离协议1；指定账号失败不回退，不更改持久权限。按钮在发送中锁定，避免重复消费。模型生成消耗真实积分，关闭等待不能保证上游停止计费。

仅管理员会话允许指定账号；非默认上游账号不在选择器中。切换国内/国际版清空选择和旧弹窗。正式 Key 的配额、账号规则与模型分组仍各自生效。

## 部署

源码从定制 GitHub main 拉取，只重建/recreate 管理端；保留现有 Docker socket 和实际 GID 挂载。用户本次要求不运行测试、不发送模型请求：仅进行必要构建、备份与部署状态检查。官方自动更新保持关闭。
